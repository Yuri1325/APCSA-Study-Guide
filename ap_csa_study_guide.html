Arithmetic operators and integer division

// Standard arithmetic
int a = 10 + 3;   // → 13  (addition)
int b = 10 - 3;   // → 7   (subtraction)
int c = 10 * 3;   // → 30  (multiplication)
int d = 10 / 3;   // → 3   ← INTEGER DIVISION: truncates toward 0
int e = 10 % 3;   // → 1   (remainder / modulo)

// Integer division: both operands must be double to get decimal result
double f = 10 / 3;          // → 3.0  (still truncates! ints divided first)
double g = (double) 10 / 3; // → 3.333...  (cast before dividing)
double h = 10.0 / 3;        // → 3.333...  (literal forces double)

// Compound assignment operators
x += 5;  // x = x + 5
x -= 2;  // x = x - 2
x *= 3;  // x = x * 3
x /= 4;  // x = x / 4
x %= 7;  // x = x % 7
x++;     // x = x + 1  (increment)
x--;     // x = x - 1  (decrement)
Most common Unit 1 mistake 7 / 2 = 3, NOT 3.5. Integer division truncates. This is the single most-tested trap in Unit 1.
Modulo uses n % 2 == 0 checks if n is even. n % 10 extracts the last digit. n % 100 extracts the last two digits.

Casting

// Explicit cast: put (type) before the value
int i = (int) 3.9;       // → 3  (truncates, does NOT round)
double d = (double) 7;   // → 7.0

// Narrowing: double → int loses decimal portion
int result = (int) (7.0 / 2);  // → 3

// Cast has higher precedence than arithmetic
(double) 5 / 2   // → 2.5  (5 cast to double first, then divided)
(double) (5 / 2) // → 2.0  (5/2=2 computed first as int, then cast)

Short-circuit evaluation && stops evaluating as soon as it sees false. || stops at first true. This prevents errors: if (arr != null && arr.length > 0) is safe — if arr is null, the second part is never evaluated.
De Morgan's Laws (tested on MCQ) !(a && b) is the same as !a || !b. And !(a || b) is the same as !a && !b.

While loop

int i = 0;
while (i < 5) {
    System.out.println(i);  // prints 0, 1, 2, 3, 4
    i++;                    // MUST update loop variable or infinite loop!
}

// Use while when you don't know how many iterations ahead of time
while (sc.hasNextInt()) {

    // always runs at least once

For loop

// Standard for loop: init; condition; update
for (int i = 0; i < 10; i++) {
    System.out.println(i);   // prints 0 through 9
}

// Iterate backwards
for (int i = 9; i >= 0; i--) {
    System.out.println(i);   // prints 9 through 0
}

// Step by 2
for (int i = 0; i <= 10; i += 2) {
    System.out.print(i + " ");  // 0 2 4 6 8 10
}

// Enhanced for loop (for-each) — no index, read-only
int[] nums = {1, 2, 3, 4, 5};
for (int n : nums) {
    System.out.println(n);   // n is a COPY — assigning to n does nothing
}
Enhanced for loop is read-only Assigning to the loop variable (e.g., n = 0; inside a for-each) does NOT change the array. Use a standard for loop if you need to modify elements.

Nested loops

// Outer loop runs M times, inner loop runs N times each → M×N total iterations
for (int row = 0; row < 3; row++) {
    for (int col = 0; col < 4; col++) {
        System.out.print("* ");
    }
    System.out.println();  // newline after each row
}
// Output: 3 rows of 4 asterisks each

Common iteration algorithms (must know for FRQ and MCQ)

// Sum of all elements
int sum = 0;
for (int n : arr) sum += n;

// Maximum — initialize to FIRST element, not 0 (broken for all-negative arrays)
int max = arr[0];
for (int n : arr)
    if (n > max) max = n;

// Minimum
int min = arr[0];
for (int n : arr)
    if (n < min) min = n;

// Count elements meeting a condition
int count = 0;
for (int n : arr)
    if (n % 2 == 0) count++;

// Average
double avg = (double) sum / arr.length;

// Build a String by concatenating each character
String result = "";
for (int i = 0; i < s.length(); i++)
    result += s.substring(i, i + 1);

// Reverse a String
String rev = "";
for (int i = s.length() - 1; i >= 0; i--)
    rev += s.substring(i, i + 1);
05 Unit 3 — Class Creation  10–18% of exam · FRQ 2 is always class design

Anatomy of a class

public class BankAccount {

    // ── Instance variables (fields) ──────────────────────
    // Always private. Each OBJECT gets its own copy.
    private String owner;
    private double balance;

    // ── Constructor ──────────────────────────────────────
    // Same name as class, no return type, sets initial state
    public BankAccount(String name, double startBalance) {
        owner = name;
        balance = startBalance;
    }

    // ── Accessor (getter) ────────────────────────────────
    // Returns a field value without modifying it
    public String getOwner() { return owner; }
    public double getBalance() { return balance; }

    // ── Mutator (setter) ─────────────────────────────────
    // Changes a field (usually void)
    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public boolean withdraw(double amount) {
        if (amount > balance) return false;
        balance -= amount;
        return true;
    }

    // ── toString ─────────────────────────────────────────
    // Called automatically by System.out.println(obj)
    public String toString() {
        return owner + ": $" + balance;
    }
}

// Using the class
BankAccount acct = new BankAccount("Alice", 1000.0);
acct.deposit(500.0);
System.out.println(acct.getBalance());   // → 1500.0
System.out.println(acct);               // → Alice: $1500.0 (calls toString)

this keyword

public class Dog {
    private String name;
    private int age;

    public Dog(String name, int age) {
        // Without "this", "name" refers to the PARAMETER (shadows the field)
        // "this.name" explicitly refers to the INSTANCE VARIABLE
        this.name = name;    // instance variable = parameter
        this.age = age;
    }
}
// Without "this": name = name; does NOTHING — assigns parameter to itself!
Silent parameter-shadowing bug If your constructor parameter has the same name as the field and you forget this., the field is never set. This is one of the most point-losing bugs on FRQ 2.

Static vs. instance

public class Counter {
    private static int totalCreated = 0;  // ONE copy, shared by ALL objects
    private int myCount = 0;              // Each object has its OWN copy

    public Counter() {
        totalCreated++;  // increment shared counter on every new Counter
    }

    public void increment() {
        myCount++;
        totalCreated++;
    }

    // Static method — called on the CLASS, not an object
    public static int getTotalCreated() {
        return totalCreated;
    }

    // Instance method — called on an OBJECT
    public int getMyCount() {
        return myCount;
    }
}

Counter.getTotalCreated();   // static: call on class name
Counter c = new Counter();
c.getMyCount();              // instance: call on object
Rules Static methods can only access static fields. Instance methods can access both static and instance fields.

Removing from an ArrayList — the index-shifting trap

// WRONG: forward loop with remove — skips elements after each remove!
for (int i = 0; i < list.size(); i++) {
    if (list.get(i).equals("Bob"))
        list.remove(i);   // element after "Bob" shifts to index i, gets skipped!
}

// CORRECT option 1: iterate backwards
for (int i = list.size() - 1; i >= 0; i--) {
    if (list.get(i).equals("Bob"))
        list.remove(i);
}

// CORRECT option 2: decrement index after remove
for (int i = 0; i < list.size(); i++) {
    if (list.get(i).equals("Bob")) {
        list.remove(i);
        i--;   // counteract the shift
    }
}

// CORRECT option 3: build a new list of items to keep
ArrayList<String> result = new ArrayList<>();
for (String s : list) {
    if (!s.equals("Bob")) result.add(s);
}

2D arrays

// Declare — [rows][cols]
int[][] grid = new int[3][4];   // 3 rows, 4 columns, all zeros
int[][] preset = {
    {1, 2, 3},
    {4, 5, 6},

// Access: ALWAYS [row][col]

for (int r = 0; r < preset.length; r++) {
    for (int c = 0; c < preset[r].length; c++) {

Searching

// ── Sequential (linear) search — works on ANY array (sorted or not) ──
public static int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) return i;   // return index if found
    }
    return -1;    // -1 means not found (convention)
}

// ── Binary search — only works on SORTED arrays ──────────────────
// On MCQ you trace binary search; writing it from scratch is rare
public static int binarySearch(int[] arr, int target, int lo, int hi) {
    if (lo > hi) return -1;                   // base case: not found
    int mid = (lo + hi) / 2;
    if (arr[mid] == target) return mid;         // found
    else if (arr[mid] < target)
        return binarySearch(arr, target, mid + 1, hi);  // search right half
    else
        return binarySearch(arr, target, lo, mid - 1);  // search left half
}
// Binary search on UNSORTED data gives WRONG results — it will NOT throw an error

Sorting — Selection sort and Insertion sort

// ── Selection sort ────────────────────────────────────────────────
// Each pass: find minimum in unsorted portion, swap it to front
// After k passes, first k elements are in final position
for (int i = 0; i < arr.length - 1; i++) {
    int minIdx = i;
    for (int j = i + 1; j < arr.length; j++) {
        if (arr[j] < arr[minIdx]) minIdx = j;
    }
    // Swap arr[i] with arr[minIdx]
    int temp = arr[i];
    arr[i] = arr[minIdx];
    arr[minIdx] = temp;
}

// ── Insertion sort ────────────────────────────────────────────────
// Each pass: take next element, shift larger elements right, insert it
// The sorted portion grows one element at a time from the left
for (int i = 1; i < arr.length; i++) {
    int key = arr[i];
    int j = i - 1;
    while (j >= 0 && arr[j] > key) {
        arr[j + 1] = arr[j];  // shift right
        j--;
    }
    arr[j + 1] = key;   // insert
}

// Note: Bubble sort is NOT on the AP exam. Merge sort may appear in tracing.
Sorting MCQ pattern "What does the array look like after k passes of selection sort?" → only the first k elements are in their final sorted positions. The rest are in no particular guaranteed order.

Recursion (tracing only in 2026 — you do NOT write recursive methods on FRQs)

// Every recursive method needs:
// 1) A base case that STOPS recursion and returns without a recursive call
// 2) A recursive case that moves TOWARD the base case

// Example: factorial
public static int factorial(int n) {
    if (n == 0) return 1;            // base case
    return n * factorial(n - 1);     // recursive case
}
// factorial(4) → 4 * factorial(3) → 4 * 3 * factorial(2) → ...
// → 4 * 3 * 2 * 1 * 1 = 24

// Tracing tip: track the call stack like a table
// Call 1: factorial(4) = 4 * factorial(3)
// Call 2: factorial(3) = 3 * factorial(2)
// Call 3: factorial(2) = 2 * factorial(1)
// Call 4: factorial(1) = 1 * factorial(0)
// Call 5: factorial(0) = 1  ← base case
// Now unwind: 1*1=1, 2*1=2, 3*2=6, 4*6=24

// Print order depends on whether print is BEFORE or AFTER recursive call
public static void countdown(int n) {
    if (n == 0) { System.out.println("Go!"); return; }
    System.out.println(n);   // print BEFORE recursive call → 3, 2, 1, Go!
    countdown(n - 1);
}
// Swap print and recursive call → Go!, 1, 2, 3 (prints on unwind)
Missing base case causes infinite recursion → StackOverflowError. An incorrect base case (fires too early) causes wrong answers silently — harder to spot.

File reading with Scanner (new for 2026)

import java.util.Scanner;
import java.io.File;

// Open a file for reading
Scanner sc = new Scanner(new File("data.txt"));

// Read all integers from a file
ArrayList<Integer> data = new ArrayList<>();
while (sc.hasNextInt()) {
    data.add(sc.nextInt());
}
sc.close();   // always close the scanner

// Read a file line by line
while (sc.hasNextLine()) {
    String line = sc.nextLine();
    // process line
}

// Read mixed data: name and score on each line
while (sc.hasNext()) {
    String name = sc.next();
    int score = sc.nextInt();
    // process name and score
}
FRQ tip On the exam, the Scanner will usually be given to you pre-constructed. You mainly need to know: which method to use to check if more data exists (hasNextInt, hasNext, hasNextLine) and which method to read one value (nextInt, next, nextLine).
nextInt() + nextLine() trap After sc.nextInt(), the newline character is still in the buffer. Calling sc.nextLine() immediately after reads that leftover newline, not the next line of actual data. Fix: call sc.nextLine() once to consume the newline before reading the next line of text.
07 Math.random() — Complete Guide

Math.random() returns a double in the range [0.0, 1.0): 0.0 is possible, 1.0 is NEVER returned.

The universal formula

// General formula for a random int from min to max (inclusive)
(int)(Math.random() * (max - min + 1)) + min
GoalFormulaRange
Random int 0–9(int)(Math.random() * 10)[0, 9]
Random int 1–10(int)(Math.random() * 10) + 1[1, 10]
Random int 1–6 (die roll)(int)(Math.random() * 6) + 1[1, 6]
Random int 5–15(int)(Math.random() * 11) + 5[5, 15]
Random int 0–100(int)(Math.random() * 101)[0, 100]
Random int -5–5(int)(Math.random() * 11) - 5[-5, 5]

Step-by-step: how the formula works

// Problem: generate a random int from 5 to 15 inclusive

// Step 1: how many possible values? 15 - 5 + 1 = 11

// Step 2: Math.random() * 11 gives a double in [0.0, 11.0)
//   possible values: 0.0, 0.001, ..., 10.999

// Step 3: (int) truncates to integer: 0, 1, 2, ..., 10
//   (never 11, because 11.0 is never produced)

// Step 4: add min (5): 5, 6, 7, ..., 15  ← desired range!
int r = (int)(Math.random() * 11) + 5;

// Simpler example: random 1–6 (dice)
int die = (int)(Math.random() * 6) + 1;

// Coin flip: random boolean
boolean heads = Math.random() < 0.5;
Parentheses matter! (int) Math.random() * 10 is WRONG — cast has higher precedence, so it casts the random double to 0 first, then multiplies. Always write (int)(Math.random() * 10).

09 Top 15 Exam Traps & Common Mistakes
  • 1
    Integer division truncates. 7 / 2 = 3, not 3.5. 1 / 3 = 0. Cast to double first: (double) 7 / 2 = 3.5. This is the single most-tested trap.
  • 2
    String == vs .equals(). == compares memory addresses. Two different String objects with the same characters will have == return false. Always use .equals() for String value comparison.
  • 3
    Off-by-one in arrays. Valid indices: 0 to arr.length - 1. Using <= instead of < causes ArrayIndexOutOfBoundsException. Using arr.length as an index is always wrong.
  • 4
    substring to is exclusive. "hello".substring(1, 3) gives "el" not "ell". The second argument is the index AFTER the last character you want.
  • 5
    ArrayList forward-remove skips elements. When you remove index i in a forward loop, the next element shifts to index i and gets skipped. Iterate backwards or decrement i after removing.
  • 6
    Math.random() parentheses. Write (int)(Math.random() * 6) + 1 not (int)Math.random() * 6 + 1. Cast applies before multiplication without the parentheses, giving always 0.
  • 7
    Strings are immutable. s.toUpperCase() does NOT change s. You must write s = s.toUpperCase() or use the result directly. All String methods return a new String.
  • 8
    Initialize max to arr[0], not 0. If the array contains all negative numbers, initializing max to 0 means no element is "greater than 0" so max stays 0 — wrong. Use Integer.MIN_VALUE or arr[0].
  • 9
    Enhanced for loop does not modify array. Assigning to the loop variable (e.g., n = 0 inside for (int n : arr)) has no effect on the array — n is a local copy. Use a standard for loop to modify elements.
  • 10
    Math.pow and Math.sqrt return double. Even Math.pow(2, 3) returns 8.0. Cast to int if you need an integer: (int) Math.pow(2, 3).
  • 11
    2D array indexing is [row][col]. MCQ frequently swaps these. If the problem says row 2, column 0, that is grid[2][0] — never grid[0][2].
  • 12
    this. parameter shadowing. In a constructor where the parameter name matches the field name, writing name = name does nothing — it assigns the parameter to itself. Write this.name = name.
  • 13
    ArrayList requires wrapper types. ArrayList<int> is a compile error. You must use ArrayList<Integer>. Java autoboxes int↔Integer automatically once you declare it correctly.
  • 14
    Double.MIN_VALUE is NOT the most negative double. It is the smallest POSITIVE nonzero double. To find the minimum in an array, initialize with Double.MAX_VALUE, not Double.MIN_VALUE.
  • 15
    Binary search requires sorted input. Applying binary search to an unsorted array does NOT throw an error — it silently returns a wrong index or -1. This is a common MCQ distractor.
10 Loop Tracing & MCQ Patterns

More than half of MCQs require tracing code — following it line-by-line and predicting output. Practice this systematically.

How to trace a loop

// Build a table: one column per variable, one row per iteration
int x = 3;
for (int i = 0; i < 3; i++) {
    x += i;
}
// i=0: x = 3 + 0 = 3
// i=1: x = 3 + 1 = 4
// i=2: x = 4 + 2 = 6
// i=3: condition 3 < 3 is FALSE → loop ends
// Final: x = 6

// MCQ trap: the update step (i++) runs AFTER the loop body but BEFORE the condition is checked again

Common MCQ question patterns

// ── Pattern 1: What does this print? ──────────────────────────
for (int i = 1; i <= 5; i++) {
    if (i % 2 == 0) System.out.print(i + " ");
}
// Output: 2 4  (only even values of i: 2 and 4)

// ── Pattern 2: How many times does this run? ──────────────────
for (int i = 2; i < 10; i += 2) { ... }
// i = 2, 4, 6, 8 → runs 4 times

// ── Pattern 3: Nested loop output ─────────────────────────────
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= i; j++) {
        System.out.print(j + " ");
    }
    System.out.println();
}
// Row 1: 1
// Row 2: 1 2
// Row 3: 1 2 3

// ── Pattern 4: Array tracing ───────────────────────────────────
int[] arr = {5, 3, 8, 1, 9};
int count = 0;
for (int i = 0; i < arr.length - 1; i++) {
    if (arr[i] > arr[i + 1]) count++;
}
// Checks pairs: (5,3)→yes, (3,8)→no, (8,1)→yes, (1,9)→no → count = 2

// ── Pattern 5: What is the value of x after this runs? ────────
int x = 1;
while (x < 100) { x *= 2; }
// x: 1→2→4→8→16→32→64→128 → loop ends when 128 ≥ 100
// Final: x = 128

MCQ strategy

Predict before looking

Cover the answer choices. Work out the answer from the code. Then match it. This prevents plausible-sounding wrong answers from swaying you.

Eliminate impossible answers

On code-tracing questions, if you know the loop runs exactly 4 times, eliminate any answer that implies 3 or 5 iterations.

Check boundary values first

What happens when the loop starts? What happens on the last iteration? Edge cases (i=0, i=length-1) are where bugs hide.

No penalty for guessing

There is no deduction for wrong answers. Mark every question, even if you have to guess. Eliminate 1–2 choices first to improve odds.
